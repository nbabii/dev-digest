## What Doesn't Work

- **2026-09-16** — An in-flow hover popover (`position: relative` wrapper + `position: absolute` panel, the pattern `@devdigest/ui`'s `Dropdown.tsx` uses) gets clipped by an `overflow: hidden` ancestor whose height auto-sizes to its content — e.g. the PR list's `tableCard`. This isn't just a "near the bottom of a long list" edge case: with a short list (even one row), the container's box ends right at the row, so the panel is clipped to a sliver almost immediately. Confirmed visually before switching to a portaled fix (see Decisions) (`client/src/components/findings-popover/FindingsPopover.tsx`).

## Decisions

- **2026-09-16** — `FindingsPopover`'s panel is rendered via `createPortal(..., document.body)` with `position: fixed`, positioned from the trigger's `getBoundingClientRect()`, instead of `Dropdown.tsx`'s in-flow absolute approach — required to escape `overflow: hidden` ancestors that auto-size to content (see What Doesn't Work). The same `onMouseEnter`/`onMouseLeave` handlers are attached to both the trigger and the portaled panel; this still works for the hover-intent gap between them because open/close is timer-based (`setTimeout` cleared on re-entry), not DOM-containment-based (`client/src/components/findings-popover/FindingsPopover.tsx`).
~- **2026-09-20** — `RunTraceDrawer`'s `PromptBlock.label` was widened from `string` to `React.ReactNode` (backward compatible — every existing caller still passes a plain string) so the Skills block's token-count could be rendered as an actual `Badge` next to the label, rather than string-concatenating the count into the label text (`client/src/app/repos/[repoId]/pulls/[number]/_components/RunTraceDrawer/_components/PromptBlock/PromptBlock.tsx`, `.../TraceBody/TraceBody.tsx`).
- **2026-09-20** — Agent editor Skills tab (drag-reorder + checkbox link/unlink, posting to the existing `POST /agents/:id/skills { skill_ids }`): local state is one full-list `order: string[]` (every workspace skill, linked ones first) plus a `checked: Set<string>`, kept separate from the live search filter. Reordering during an active filter maps the drag (observed within the filtered subset) back onto the full order via `reorderFullOrder(fullOrder, filteredIds, activeId, overId)`, using the active/over items' relative position *within the filtered view* to decide insert-before vs. insert-after in the full array — avoids silently losing hidden (filtered-out) items' relative order, a common bug when you reorder the filtered array alone (`client/src/app/agents/[id]/_components/AgentEditor/_components/SkillsTab/helpers.ts`).
- **2026-09-20** — Conventions Extractor spec (`client/specs/conventions-extractor.md`): `client/messages/en/conventions.json`'s pre-seeded card copy (single `acceptAsSkill` key, no reject key) implies a per-candidate "accept → instantly becomes its own skill" flow, but the written requirement and both provided mockups describe a batch flow (accept/reject many candidates, then merge all accepted ones into one skill via a review modal). Resolved in favor of the written requirement + mockups, `acceptAsSkill` repurposed as the accept-toggle's label rather than a per-candidate skill-creation action, and the conflict written into the spec instead of silently picked. Pre-seeded i18n copy in this repo is aspirational/illustrative (same pattern as `skills.json` before the Skills feature), not a spec of record — cross-check it against the actual written requirement before trusting it as ground truth.

## Recurring Errors & Fixes

- **2026-09-16** — Setting only `overflowY: "auto"` (leaving `overflowX` unset) produced a stray horizontal scrollbar on a panel that never intentionally overflows sideways. Cause: per the CSS overflow spec, if one of `overflow-x`/`overflow-y` is set to a non-`visible` value and the other is left at its initial `visible`, the browser computes the `visible` one as `auto` too — so `overflowY: auto` silently implies `overflowX: auto`. Fix: always set `overflowX` explicitly (e.g. `"hidden"`) whenever `overflowY` is set on a container that shouldn't scroll horizontally (`client/src/components/findings-popover/FindingsPopover.tsx`).
- **2026-09-16** — Don't hardcode a popover/panel's `maxHeight` (e.g. a flat `360`) — short content will scroll unnecessarily even when it would easily fit. Compute it from actual remaining space instead: `Math.min(CAP, window.innerHeight - triggerRect.bottom - margin)` at open time (`client/src/components/findings-popover/FindingsPopover.tsx`).
- **2026-09-20** — In a deeply-nested colocated component folder (`src/app/<feature>/[id]/_components/<Editor>/_components/<Tab>/Foo.tsx`), it's easy to miscount relative-import `../` depth by one — and the miscount differs by target: from `.../AgentEditor/_components/ConfigTab/` (or any sibling tab folder at that same depth) it's 7×`../` to `client/src/lib/hooks/*` but 8×`../` to `client/messages/en/*.json`, because `messages/` sits one level above `src/`. Symptom: `TS2307: Cannot find module`, plus cascading `TS7006 implicit any` on anything typed from the now-unresolved import. The visual difference between 6 and 7 `../` groups is easy to miscount by eye in editor/tool output — verify instead with `node -e "console.log(require('path').resolve('.', '<relative>'))"` run from the actual file's directory.

## Codebase Patterns & Tool Notes

- **2026-09-16** — `client/src/lib/types.ts` can contain unused, pre-scaffolded types that hint at an intended-but-not-yet-built shape — e.g. `PrRowView.findings: {CRITICAL,WARNING,SUGGESTION}` already existed there, unused, before the findings-counter feature was implemented, and matched the shape the new `PrMeta.findings` field ended up needing. Worth grepping `lib/types.ts` for a matching unused type before designing a new contract shape from scratch.
- **2026-09-20** — `@devdigest/ui`'s `Badge` has no `title` prop (only `children`/`color`/`bg`/`icon`/`dot`/`mono`/`style`) — passing `title` to it silently does nothing (no type error surfaces the mistake in an obviously visible way). For a tooltip on a badge, wrap it in a plain `<span title="...">` instead (`client/src/app/skills/_components/SkillCard/SkillCard.tsx`).
- **2026-09-20** — When a client-side spec says to build against a server contract that's landing in parallel (not yet merged when the client work starts), don't trust a spec's prose description of a response shape as complete even when it looks fully specified — check the actual server module once it lands. Example: `client/specs/skills.md` described the import-preview zip-ignored-entries shape as `{ path, ignored: true }` but never named the wrapping response field; the real server implementation (`server/src/modules/skills/import-parser.ts`) used `ignored`, not the guessed `ignored_entries`. Caught by grepping `server/src/modules/skills/*.ts` directly after the server side landed, before finalizing `client/src/lib/hooks/skills.ts`.
